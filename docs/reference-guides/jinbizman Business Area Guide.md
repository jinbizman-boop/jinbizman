좋습니다.
이번에는 **사업분야 파트만** 고도화해서, **홈페이지 문구/구조/UI/UX**와 **ERP 분류체계/운영 구조**에 바로 적용될 수 있게 정리하겠습니다.

현재 첨부 파일의 핵심 의도는 분명합니다.
진비즈 매니지먼트를 단순 “AI 서비스 회사”가 아니라, **AI를 중심 엔진으로 삼아 신소재·에너지·국방기술·생활복지까지 확장하는 미래 산업형 그룹 구조**로 보이게 하려는 것입니다. 그리고 이 5개 사업군을 단순 나열하지 않고, **“사이버트론 프로젝트”라는 하나의 상위 비전** 아래 묶으려는 의도입니다. 또 UI/UX도 “사업군 소개 → 하단 사이버트론 프로젝트 → 각 사업군이 활성화될 때 메카 파츠가 점등되는 방식”으로 명확히 지정돼 있습니다. 

이 방향은 기존 JINBIZ 확정 기준인 **외부 회사소개형 홈페이지 + 내부 WBS 중심 ERP + 5개 공식 언어 + `www.jinbizman.com` 기준 운영**과도 충돌하지 않습니다. 그래서 이번 고도화는 기존 구조를 깨지 않고, **사업소개 파트만 상위 전략 영역으로 확장**하는 방식으로 맞추는 것이 가장 좋습니다.

## 1. 의도 파악 결과

지금 사업분야 파일은 사실상 아래 구조를 원합니다.

**1단계**
진비즈의 사업군을 5개 축으로 재정의

* 인공지능 사업군
* 신소재 사업군
* 에너지 사업군
* 국방기술 사업군
* 생활복지 사업군

**2단계**
이 5개를 따로따로 보이게 하지 않고,
**“사이버트론 프로젝트”**라는 상위 프로젝트 아래 **유기적으로 연결된 미래 산업 포트폴리오**처럼 보이게 만들기

**3단계**
홈페이지에서는 비전형 브랜드 스토리로,
ERP에서는 실제 **사업군 분류 / 서비스 분류 / 프로젝트 분류 / WBS 템플릿 분류**로 연결하기

즉, 이건 단순 메뉴 문구 수정이 아닙니다.
**사업소개 페이지의 정체성**, **서비스 허브 분류 체계**, **프로젝트/WBS 운영 기준**까지 같이 바꾸는 기준값입니다.

## 2. 사업분야 파트 최종 고도화 방향

### 상위 정의

사업소개 페이지의 최상위 제목은 이제 이렇게 바꾸는 것이 좋습니다.

**사업분야**
진비즈 매니지먼트는 인공지능을 핵심 엔진으로 삼아,
신소재·에너지·국방기술·생활복지까지 연결되는 미래 산업 융합 구조를 설계합니다.

이 문장은 좋은 이유가 있습니다.

* AI를 중심에 둡니다.
* 다른 4개 분야가 AI와 분리되지 않습니다.
* “여러 사업을 조금씩 하는 회사”가 아니라 **하나의 대형 프로젝트를 추진하는 회사**처럼 보입니다.
* ERP에서도 상위 포트폴리오 개념으로 쓰기 쉽습니다.

## 3. 홈페이지용 최종 사업분야 카피

아래 문구는 그대로 사업소개 페이지에 넣어도 되는 수준으로 정리한 버전입니다.

### 3-1. 사업분야 섹션 메인 카피

**미래 산업을 연결하는 5대 사업군**

진비즈 매니지먼트는 인공지능을 중심 축으로,
신소재·에너지·국방기술·생활복지까지 이어지는 미래 산업 구조를 준비합니다.
각 사업군은 독립적으로 존재하지 않고, 하나의 통합 비전 아래 상호 연결됩니다.

---

### 3-2. 5개 사업군 고도화 문구

#### 1) 인공지능 사업군

**지능의 엔진을 만드는 분야**

차세대 인공지능 기술을 기반으로
판단, 생성, 분석, 제어가 가능한 지능형 시스템을 설계합니다.
진비즈의 모든 확장 사업군은 이 인공지능 역량을 중심 엔진으로 삼습니다.

#### 2) 신소재 사업군

**미래 구조를 지탱하는 기반 소재 분야**

고기능성 소재, 경량화, 내구성, 열관리, 차세대 복합소재 등
미래 산업 구조의 하드웨어 기반이 되는 소재 기술을 다룹니다.
에너지·국방·산업 플랫폼으로 확장될 수 있는 기반 축입니다.

#### 3) 에너지 사업군

**지속 가능한 동력을 만드는 분야**

에너지 저장, 전환, 효율 관리, 차세대 전력 운용 구조를 중심으로
미래 시스템의 안정적인 동력 인프라를 구축합니다.
AI 및 신소재 기술과 결합해 자율적 에너지 최적화 구조를 지향합니다.

#### 4) 국방기술 사업군

**지능형 방위 기술과 전략 시스템 분야**

지능형 감시, 판단 지원, 무인화, 보안, 전략 의사결정 보조 등
미래 국방 환경에 필요한 기술 체계를 준비합니다.
AI·에너지·신소재 기술과 융합되는 고신뢰 분야입니다.

#### 5) 생활복지 사업군

**기술의 가치를 사람의 삶으로 연결하는 분야**

생활 안전, 건강, 복지, 돌봄, 접근성 향상 등
기술이 실제 사람의 삶에 닿는 실용적 가치를 만듭니다.
진비즈의 기술이 궁극적으로 어디에 닿아야 하는지를 보여주는 최종 응용 영역입니다.

## 4. 사이버트론 프로젝트 파트 고도화

파일상 이미 아래 의도가 있습니다.

* AI = 트랜스포머의 뇌
* 에너지 = 트랜스포머의 심장
* 나머지는 일부 미완성 상태

그래서 이 부분은 그대로 두지 말고, **완성형 체계**로 정리하는 것이 맞습니다. 

### 4-1. 권장 완성형 매핑

#### 사이버트론 프로젝트

**미래 산업 융합 비전 프로젝트**

* 인공지능 사업군 = **사이버트론의 뇌**
* 신소재 사업군 = **사이버트론의 골격**
* 에너지 사업군 = **사이버트론의 심장**
* 국방기술 사업군 = **사이버트론의 방패**
* 생활복지 사업군 = **사이버트론의 감각**

이 구조가 좋은 이유는 명확합니다.

* 각 사업군 역할이 바로 이해됩니다.
* 사용자가 말한 “하나씩 완성되면 불이 들어오는 활성화 UX”와 정확히 맞습니다.
* 홈페이지 브랜딩과 ERP 분류 코드 둘 다에 쓰기 쉽습니다.

## 5. 홈페이지 UI/UX 적용 방식

### 5-1. 가장 좋은 섹션 순서

1. 사업분야 섹션 헤더
2. 5개 사업군 카드
3. 하단 “사이버트론 프로젝트” 비주얼 섹션
4. 각 카드 hover/click 시 해당 파츠 점등
5. 5개 모두 활성 상태가 되면 중앙 코어 점등 애니메이션

### 5-2. 카드 UI 구조

각 카드 안에는 아래만 넣는 게 좋습니다.

* 사업군명
* 한 줄 정의
* 2줄 설명
* “사이버트론에서의 역할” 배지

예시:

* 인공지능 사업군
  지능의 엔진
  사이버트론의 뇌

* 신소재 사업군
  구조의 기반
  사이버트론의 골격

### 5-3. 하단 비주얼 UX

사용자가 원하는 방향은 유지하되, **직접 옵티머스 프라임 같은 실존 캐릭터 디자인은 쓰지 않는 것**이 안전합니다.
대신 아래처럼 가면 됩니다.

* “변신형 메카” 실루엣
* 중앙 코어형 심장부
* 머리/골격/심장/방패/감각 노드에 각 사업군 연결
* hover 또는 tab 전환 시 해당 파츠 glow
* 모바일에서는 세로형 인터랙션
* 데스크톱에서는 좌우 카드 + 중앙 메카 구조

즉, **직접 캐릭터 사용이 아니라 ‘사이버트론 프로젝트 전용 메카 실루엣’**으로 가는 것이 맞습니다.

## 6. ERP에 적용하는 방식

이제 중요한 부분입니다.
이 사업분야는 홈페이지 문구로 끝나면 안 되고, ERP에서 **실제 운영 분류 체계**가 되어야 합니다.

### 6-1. ERP 상위 분류 코드로 추가

사업군 코드는 아래처럼 고정하는 것이 좋습니다.

```ts
export const BUSINESS_DOMAIN_CODES = [
  "ai",
  "materials",
  "energy",
  "defense",
  "welfare",
] as const;
```

### 6-2. 사이버트론 모듈 코드

```ts
export const CYBERTRON_MODULE_CODES = [
  "brain",
  "frame",
  "heart",
  "shield",
  "senses",
] as const;
```

### 6-3. ERP 적용 위치

이 코드는 최소 아래 4군데에 반영하는 것이 맞습니다.

* `services.business_domain_code`
* `projects.business_domain_code`
* `wbs_templates.business_domain_code`
* `service_change_logs` 또는 프로젝트 리포트 집계 기준

### 6-4. 실제 운영상 좋아지는 점

이렇게 바꾸면 ERP에서 바로 가능합니다.

* 서비스 허브에서 사업군별 필터
* 프로젝트 생성 시 사업군 선택
* WBS 템플릿을 사업군별로 다르게 제공
* 결재 문서도 사업군별 승인 흐름 분기
* 평가도 사업군별 KPI 차등 적용
* 대시보드에서 사업군별 진행률, 리스크, 문의 전환율 집계

즉, 홈페이지의 “사업분야”가 ERP의 “운영 분류 체계”가 됩니다.

그리고 **ERP에서 바로 쓸 분류 코드 / DB 컬럼 / API 반영안**을 한 번에 정리합니다.

이번 정리는 기존 확정 방향을 깨지 않는 범위에서 진행해야 합니다.
즉 기존 사업소개 페이지의 큰 축인 **`AI 서비스 → 플랫폼 사업 → 기획 서비스`** 흐름은 유지하되, 그 안에 새로 확정한 **5대 사업군 + 사이버트론 프로젝트**를 상위 전략 구조로 넣는 방식이 맞습니다. 이 방식이 현재 가이드의 외부 홈페이지 방향, 서비스 허브 중심 ERP, WBS 중심 운영, 5개 공식 언어, `www.jinbizman.com` 기준 운영과 충돌하지 않습니다.

## 1. 최종 방향 정리

현재 사업분야 파일이 요구하는 핵심은 아래입니다.

* 사업군을 **인공지능 / 신소재 / 에너지 / 국방기술 / 생활복지** 5축으로 재정의
* 이 5개를 **“사이버트론 프로젝트”**라는 상위 비전 아래 묶기
* UI는 **사업군 소개 후 하단에 사이버트론 프로젝트**
* 사업군 하나씩 활성화될 때 **메카 파츠가 점등되는 방식**으로 표현 

이걸 그대로 구현하되, 기존 사업소개 페이지의 3축 구조는 버리면 안 됩니다.
그래서 최종적으로는 아래처럼 정리하는 게 가장 맞습니다.

### BusinessPage의 최종 정보 구조

1. 사업소개 페이지 헤더
2. 사업의 큰 방향 설명
3. 기존 3개 사업축

   * AI 서비스
   * 플랫폼 사업
   * 기획 서비스
4. 5대 사업군 포트폴리오

   * 인공지능
   * 신소재
   * 에너지
   * 국방기술
   * 생활복지
5. 사이버트론 프로젝트 비전 섹션
6. 진비즈의 실행 방식
7. CTA

즉,
**3개 사업축은 “사업 구조”**,
**5대 사업군은 “확장 포트폴리오”**,
**사이버트론 프로젝트는 “상위 미래 비전”**으로 두는 방식입니다.

alter table services

  check (cybertron_module_code in ('brain', 'frame', 'heart', 'shield', 'senses'));

### 7-6. 이유

이렇게 해야 아래가 됩니다.

* 서비스 허브에서 사업군별 필터 가능
* 프로젝트 생성 시 사업군 선택 가능

* 결재를 사업군별 승인 흐름으로 분기 가능

* 대시보드에서 사업군별 문의, 프로젝트, 리스크 집계 가능

이건 직전 사업분야 고도화 의도와 정확히 같습니다.
