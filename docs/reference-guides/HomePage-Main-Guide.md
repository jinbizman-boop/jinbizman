# JINBIZ MANAGEMENT 홈페이지 + ERP 최신형 완성 최종본

## 1. 최종 결론

진비즈 매니지먼트의 새 프로젝트는 아래처럼 최종 정의하는 것이 가장 정확합니다.

> **JINBIZ MANAGEMENT는 AI 서비스와 플랫폼 사업을 전개하는 회사입니다.**
> **기획 역량은 기반이고, AI 서비스가 현재의 중심이며, 플랫폼 사업이 다음 확장축입니다.**

그리고 내부 시스템은 아래처럼 정의하는 것이 맞습니다.

> **JINBIZ MANAGEMENT ERP는 단순 홈페이지 관리 CMS가 아니라,**
> **콘텐츠 운영 + 문의/리드 관리 + 전자결재 + 프로젝트/WBS + 조직/권한 + 경영지원이 하나의 계정 체계로 이어지는 통합 운영 시스템입니다.**

즉, 이 프로젝트는 처음부터 아래 2가지를 동시에 갖습니다.

* 외부용: **회사소개형 AI 서비스 기업 홈페이지**
* 내부용: **ERP형 통합 운영 관리자**

이 방향은 첨부 실행 문서와 프론트/백엔드 가이드에서 일관되게 고정된 방향입니다. 외부는 회사소개형 AI 홈페이지, 내부는 WBS 중심 ERP이며, 서비스 허브·업무보고/업무일지·평가 근거 데이터가 핵심이라고 이미 정리돼 있습니다.

## 2. 이번에 추가로 최종 확정되는 핵심 3가지

이번 문서에서 아래 3가지를 **정식 요구사항**으로 추가 확정합니다.

### 2-1. 대표 도메인 확정

대표 도메인은 **`www.jinbizman.com`** 으로 확정합니다.
이미 구매 완료된 도메인이므로, 외부 홈페이지의 대표 주소, 공용 링크, SEO canonical, 뉴스 상세 URL, 문의 완료 링크, 이메일 서명 링크 모두 이 도메인을 기준으로 통일합니다.

운영 원칙은 아래처럼 고정합니다.

* 대표 canonical 도메인: `https://www.jinbizman.com`
* 루트 도메인 `jinbizman.com`은 `www.jinbizman.com`으로 301 리다이렉트
* 모든 공개 페이지, 뉴스 상세, 문의 완료, 언어별 페이지는 이 대표 도메인 아래에서 운영
* ERP는 동일 도메인 하위 경로 또는 서브도메인 전략을 택할 수 있으나, 1차 기준 문서상 운영 일관성을 위해 같은 프로젝트 안에서 관리

### 2-2. 전 기기/전 환경 반응형 웹앱 확정

이 프로젝트는 **외부 홈페이지와 내부 ERP 모두** PC, 모바일, 태블릿 등 모든 기기와 환경에서 **깨지거나 이탈되거나 가로로 밀리는 현상 없이 완전한 상태로 보여야 하는 반응형 웹앱**으로 확정합니다.

이건 선택 옵션이 아니라 필수 구현 조건입니다.

### 2-3. 공식 지원 언어 확정

대외 공개 서비스는 아래 5개 언어를 **공식 지원**합니다.

* 한국어
* 영어
* 일본어
* 불어
* 스페인어

관리 원칙은 아래처럼 갑니다.

* 외부 공개 페이지와 공개 뉴스/공지성 콘텐츠는 5개 언어 운영을 기본 지원
* 내부 ERP는 1차 운영 언어를 한국어 중심으로 두되, **언어별 콘텐츠 관리·미리보기·발행 제어는 처음부터 지원**
* 서비스 허브와 콘텐츠 모델 설계에는 `i18n_enabled` 개념을 반영

첨부 실행 문서와 백엔드 가이드에도 이미 서비스 허브의 `services` 테이블에 `i18n_enabled`가 포함되어 있어, 다국어 확장은 구조적으로도 맞는 방향입니다.

## 3. 벤치마킹 해석 최종본

SK 공식 사이트는 회사 소개, 산업, 뉴스, 회사 정보 구조가 명확하게 분리돼 있고 “공식 회사 사이트다운 안정감”이 강합니다. 솔트룩스는 엔터프라이즈 AI, 생성형 AI, 디지털 플랫폼 정부, 금융 지능화 같은 사업 설명을 전면에 두어 “무엇을 하는 회사인지”를 사업 중심으로 풀어냅니다. 그래서 진비즈 외부 홈페이지는 **SK식 신뢰 구조 + 솔트룩스식 사업 설명 구조**를 결합하는 것이 가장 적합합니다. ([SK][1])

내부 ERP는 다른 기준으로 봐야 합니다. 하이웍스는 인사관리, 근무관리, 경비지출관리, 무료 메신저, 전자결재, 세금계산서를 묶은 올인원 운영 구조를 전면에 내세우고, 이카운트는 판매·구매·재고·생산·회계·급여·그룹웨어를 한 ERP에 넣고 입력 즉시 보고서에 반영되는 실시간 보고와 메뉴 재구성을 강조합니다. 네이버웍스는 메시지·메일·캘린더·할 일·게시판·설문·드라이브와 함께 결재·인사·근태를 묶어 하나의 협업/경영지원 플랫폼으로 설명합니다. 따라서 진비즈 ERP는 **운영 흐름 + 데이터 흐름 + 협업 흐름**이 하나로 이어지는 구조가 맞습니다. ([하이웍스][2])

유레카월드 설계안은 이 전체 방향을 시각적으로 묶어줍니다. 첨부 문서들에서도 유레카월드는 단순 대화형 AI가 아니라 **작업 중심 AI 서비스**로 소개되어야 하고, 내부 운영은 WBS·업무보고·평가 근거까지 연결되어야 한다고 반복해서 정리돼 있습니다.

* 고정 높이로 인해 텍스트 잘림 금지
* Hero, 카드, 탭, 표, 폼은 다국어 문자열 길이를 고려한 유연 높이 사용

# 11. 관리자 페이지 최종본 — CMS가 아닌 ERP 시스템

이제 가장 중요한 부분입니다.

관리자 페이지는 더 이상 “글 등록하고 문구 수정하는 CMS”가 아닙니다.
처음부터 **ERP 시스템**으로 갑니다.

즉 이 시스템은 아래를 동시에 처리해야 합니다.

* 홈페이지 운영
* 뉴스/공지 운영
* 문의/리드 관리
* 전자결재
* WBS/프로젝트 관리
* 조직/인사/근태
* 경비/지출/정산
* 문서/파일/자산
* 보고서/통계
* 권한/감사로그
* 다국어 콘텐츠 운영
* 반응형 관리자 웹앱 운영

백엔드/실행 문서도 관리자 핵심을 서비스 허브, WBS 중심 업무, 아침 업무보고 + 퇴근 업무일지, 업무 데이터 기반 평가로 정의하고 있습니다.  

---

## 11-1. ERP의 최종 정의

> **JINBIZ ERP는 대외 홈페이지 관리와 대내 운영 업무를 하나의 계정 체계로 연결하는 통합 운영 시스템이다.**

즉 외부 홈페이지를 수정하는 사람도 같은 ERP 안에서 일하고,
문의 담당자도 같은 ERP 안에서 일하고,
전자결재 담당자도 같은 ERP 안에서 일하며,
프로젝트/WBS 담당자도 같은 ERP 안에서 일해야 합니다.

하이웍스, 이카운트, 네이버웍스가 각각 운영 허브, 실시간 데이터 흐름, 통합 업무 플랫폼의 강점을 보여주는 만큼, 진비즈 ERP도 “운영 전반을 하나의 관리자 안에 묶는 구조”가 맞습니다. ([하이웍스][2])

---

## 11-2. ERP 설계 원칙

### 1) 단일 로그인

모든 관리자 기능은 하나의 계정으로 접근합니다.

### 2) 모듈형 ERP

여러 모듈이 있어도 하나의 ERP 안에서 연결됩니다.

### 3) 결재 중심 운영

전자결재가 운영의 중심 허브 역할을 합니다.

### 4) 프로젝트/WBS 중심

모든 실무 기록은 프로젝트/WBS에 연결됩니다.

### 5) 홈페이지와 ERP의 완전 연결

외부 홈페이지 콘텐츠는 ERP 안에서만 등록/수정됩니다.

### 6) 다국어 콘텐츠 운영 내장

관리자 ERP는 5개 언어 콘텐츠를 운영할 수 있어야 합니다.

### 7) 전 기기 반응형 관리자

ERP도 PC, 모바일, 태블릿에서 깨짐 없이 동작해야 합니다.

첨부 문서에서도 서비스 허브, WBS, 업무보고/일지, 평가까지 ERP 구조에 포함되어야 하고, 새 서비스가 생겨도 서비스 등록만으로 연결되어야 한다고 반복됩니다.

## 14-1. 외부 홈페이지 공통 구현 원칙

### 공통 셸

* 상단 헤더는 외부 5개 페이지에서 동일 구조를 유지합니다.
* 로고 클릭 시 현재 언어의 홈으로 이동합니다.
* 메뉴 활성 상태는 현재 라우트를 기준으로 표시합니다.

* 외부 페이지의 콘텐츠 폭은 `max-width` 기반으로 제한합니다.
* 대형 화면에서는 콘텐츠 폭만 제한하고 배경은 전체 폭 사용이 가능합니다.
* 각 섹션은 상하 여백을 충분히 주되, 모바일에서는 과한 공백을 줄입니다.

* 페이지 헤더, 섹션 타이틀, CTA, 리스트 카드, 빈 상태, 에러 상태는 공통 컴포넌트로 관리합니다.
* 언어가 길어지는 프랑스어/스페인어 기준으로 최소 폭을 검증합니다.
* 일본어는 줄바꿈이 짧게 끝나더라도 컴포넌트 높이를 강제 축소하지 않습니다.

외부 공개 페이지는 모두 아래 상태를 기본으로 가집니다.

* 빈 데이터 상태
* 에러 상태

# 20. WBS 중심 운영 체계 최종 통합본

## 20-1. 운영 원칙

* 모든 업무는 프로젝트에 속합니다.
* 모든 실무는 WBS에 연결됩니다.
* 모든 보고는 WBS를 참조합니다.
* 모든 산출물은 WBS와 연결됩니다.
* 모든 평가 근거는 WBS 실행 데이터에서 수집됩니다.

## 20-2. 표준 흐름

* 일정 지연 원인을 분석할 수 있습니다.
* 외부 문의를 실제 프로젝트로 전환한 뒤 후속 추적이 가능합니다.

# 26. 5단계 배포 완료 기준 최종안

이 장은 이번 문서에서 반드시 반영해야 하는 **실행형 배포 완료 기준**입니다.  
문서를 읽는 순간 바로 구현 우선순위를 잡을 수 있어야 하므로, 아래 5단계를 최종 기준으로 고정합니다.

## 26-1. 1단계 배포 완료 기준 — 외부 브랜드 골격 완성

### 포함 범위

* 메인 홈
* 회사소개
* 사업소개
* 뉴스레터 리스트 골격
* 문의하기 화면 골격
* 공통 헤더/푸터
* 디자인 토큰 1차 적용

### 완료 기준

* 방문자가 첫 화면에서 AI 서비스 회사로 인식
* 5개 메뉴 구조 고정
* 회사소개에 대표 인사말/과도한 CTA 없음
* 사업소개 순서가 올바름
* 뉴스레터가 3탭 구조를 가짐
* 문의 페이지가 실제 폼 형태를 가짐
