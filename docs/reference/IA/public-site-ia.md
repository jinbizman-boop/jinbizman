# JINBIZ Public Site IA 최신형 완성형 최종본

## 이번 단계 목표

* 첨부 기준 문서들과 지금까지 확정된 채팅 방향을 모두 반영해 **`docs/IA/public-site-ia.md` 최신형 완성형 최종본**을 다시 정리합니다.
* 이번 문서는 `JINBIZ MANAGEMENT`의 외부 공개 홈페이지만을 대상으로 하는 **공개 사이트 정보구조(IA) 실행 기준서**입니다.
* 기존 확정안에 아래 3가지를 정식 요구사항으로 추가 확정합니다.

  * **PC, 모바일, 태블릿 등 모든 기기와 모든 환경에서 깨지거나 이탈되지 않는 반응형 웹앱**
  * **한국어, 영어, 일본어, 불어, 스페인어 공식 지원**
  * **대표 도메인 `www.jinbizman.com` 사용**

* 이번 최종본은 보기 좋은 사이트맵 문서가 아니라 **바로 라우팅, 페이지 설계, 섹션 구성, SEO, 번역 운영, 구현 순서로 이어질 수 있는 공개 사이트 IA 기준서**로 작성합니다.
* `HomePage-Main-Guide`, `Frontend-Develop-Guide`, `Develop-Total-Guide`, `Development-Execution`에 공통으로 반영된 **외부 5개 메뉴 / 뉴스레터 3탭 / 문의 저장 구조 / 5개 언어 / canonical / 반응형 / 5단계 배포 완료 기준**을 외부 사이트 IA로 재조립합니다.

## 확인 방법

아래가 맞으면 이번 공개 사이트 IA 문서는 정상으로 봐도 됩니다.

* 외부 홈페이지의 1차 메뉴가 **메인 홈 / 회사소개 / 사업소개 / 뉴스레터 / 문의하기** 5개로 명확히 고정되어 있는지
* 뉴스레터 메뉴가 실제로는 **보도자료 / 공시정보 / 공지사항** 3개 구조로 설명되어 있는지
* 사이트 전체 흐름이 **첫인상 → 이해 → 신뢰 → 소식 확인 → 문의 전환**으로 자연스럽게 이어지는지
* 외부 사이트가 **AI 서비스 회사**로 3초 안에 인식되도록 IA가 설계되어 있는지
* 회사소개는 대표 인사말 없이 신뢰 형성 중심으로 정리되어 있는지
* 사업소개는 **AI 서비스 → 플랫폼 사업 → 기획 서비스** 순서를 유지하는지
* 5개 언어 URL 구조와 canonical 기준이 `www.jinbizman.com`으로 고정되어 있는지
* 모바일/태블릿/데스크톱에서 메뉴와 섹션 구조가 어떻게 바뀌는지 반응형 IA 규칙이 포함되어 있는지
* 문의하기가 단순 폼이 아니라 **저장 + 후속 운영 연결의 시작점**으로 설명되어 있는지
* 문서 마지막 체크리스트만 봐도 기존 파일을 즉시 대체할 수 있는지 확인 가능한지
* 5단계 배포 완료 기준이 외부 공개 사이트 구현 순서에 맞게 포함되어 있는지

## 문제 발생 시

* 메뉴만 나열하고 페이지 역할을 설명하지 않으면 실제 구현에서 섹션 우선순위가 흔들립니다.
* 첫 화면에서 AI 서비스 회사로 인식되지 않으면 외부 IA 전체가 약해집니다.
* 회사소개에 대표 인사말이나 과한 문의 유도를 넣으면 기존 확정 방향과 어긋납니다.
* 사업소개에서 순서가 바뀌면 `AI 서비스 중심 + 플랫폼 확장 + 기획 기반 역량` 구조가 흐려집니다.
* 뉴스레터를 구독형 뉴스레터로 오해하면 `보도자료 / 공시정보 / 공지사항` 구조가 깨집니다.
* 문의하기를 단순 연락처 페이지로만 잡으면 CRM/리드 전환 구조와 연결이 약해집니다.
* 다국어를 IA 마지막에만 덧붙이면 실제 URL/SEO/발행 구조에서 빠집니다.
* 반응형을 스타일 문제로만 보면 모바일 내비게이션, 카드 순서, CTA 스택 같은 핵심 흐름이 빠집니다.
* 5단계 배포 완료 기준을 빼면 구현 우선순위와 검수 기준이 다시 흔들립니다.

# 1. 최종 정의

이 문서에서 말하는 공개 사이트 IA의 정답은 단순한 “회사 홈페이지 메뉴 구조”가 아닙니다.

정답은 아래입니다.

> **JINBIZ Public Site IA는 AI 서비스 회사로서의 첫인상, 회사 정체성 설명, 사업 구조 이해, 공식 소식 아카이브, 문의 전환 흐름을 하나의 브랜드·하나의 도메인·하나의 다국어 정책 안에서 연결하는 외부 공개 정보구조다.**

이 IA는 아래 전제를 반드시 지켜야 합니다.

* 외부 홈페이지는 **회사소개형 AI 서비스 기업 홈페이지**다.
* 첫 화면에서 **AI 서비스 회사**로 인식되어야 한다.
* 상단 메뉴는 **메인 홈 / 회사소개 / 사업소개 / 뉴스레터 / 문의하기** 5개로 고정한다.
* 뉴스레터는 이름만 뉴스레터이고 실제 운영 구조는 **보도자료 / 공시정보 / 공지사항**이다.
* 사업 구조는 **AI 서비스 → 플랫폼 사업 → 기획 서비스** 순서로 유지한다.
* 대표 도메인은 항상 **`www.jinbizman.com`** 이다.
* 공식 지원 언어는 항상 **`ko`, `en`, `ja`, `fr`, `es`** 이다.
* 외부 공개 사이트도 **반응형 웹앱** 전제를 가져야 한다.
* 외부 공개 사이트는 내부 ERP와 브랜드/디자인 토큰을 공유하되, 사용자 경험은 더 단정하고 간결해야 한다.

# 2. 공개 사이트 IA 설계 원칙

## 2-1. 3초 인식 원칙

첫 화면 3초 안에 방문자가 “이 회사는 AI 서비스와 플랫폼을 하는 회사구나”라고 이해해야 합니다.

## 2-2. 5메뉴 고정 원칙

외부 홈페이지의 메뉴 수는 늘리지 않습니다.

* 메인 홈
* 회사소개
* 사업소개
* 뉴스레터
* 문의하기

이 구조는 이미 확정된 방향이므로 흔들지 않습니다.

## 2-3. 회사소개와 사업소개 분리 원칙

* 회사소개는 **정체성 / 비전 / 가치 / 연혁** 중심
* 사업소개는 **무엇을 제공하는지** 중심

둘을 섞으면 정보 구조가 흐려집니다.

## 2-4. 뉴스레터는 소식 센터 원칙

메뉴명은 뉴스레터지만, 실제 운영은 다음 3개입니다.

* 보도자료
* 공시정보
* 공지사항

1차 오픈에서는 구독형 뉴스레터가 아닙니다.

## 2-5. 문의는 전환 시작점 원칙

문의하기는 단순 연락처 페이지가 아니라, **외부 관심 → 내부 문의/리드 운영**으로 이어지는 시작점입니다.

## 2-6. 다국어와 도메인은 IA의 일부 원칙

언어 전환과 canonical 구조는 IA 끝에 덧붙이는 것이 아니라, 처음부터 라우트/SEO/콘텐츠 위계에 포함되어야 합니다.

## 2-7. 모바일 우선 원칙

외부 공개 사이트는 데스크톱 기준 디자인보다 **모바일에서 정보가 자연스럽게 흘러가는 구조**를 우선합니다.

## 2-8. 5단계 배포 연결 원칙

공개 사이트 IA는 화면 소개에서 끝나면 안 됩니다.
문서를 읽는 순간 **어떤 화면을 먼저 만들고, 어디까지를 배포 완료 기준으로 볼지** 바로 이해되어야 합니다.

# 3. 공개 사이트 전체 구조 한눈에 보기

공개 사이트는 아래 5단계 흐름으로 이해하면 가장 정확합니다.

1. **첫인상**
   * 메인 홈

2. **신뢰 형성**
   * 회사소개

3. **이해와 설득**
   * 사업소개

4. **공식 소식 확인**
   * 뉴스레터

5. **문의 전환**
   * 문의하기

즉, 공개 사이트 IA는 아래 흐름을 따라야 합니다.

```text
메인 홈
  ↓
회사소개
  ↓
사업소개
  ↓
뉴스레터
  ↓
문의하기
```

이 흐름은 외부 홈페이지 기준 문서의 “AI 서비스 회사 인식 → 회사 정체성 → 사업 구조 → 소식 → 문의” 구조와 맞습니다.

# 14. 5단계 배포 완료 기준 — 공개 사이트 IA 반영본

이 장은 이번 문서에서 반드시 반영해야 하는 **실행형 배포 완료 기준**입니다.
문서를 읽는 순간 바로 구현 우선순위를 잡을 수 있어야 하므로, 아래 5단계를 외부 공개 사이트 기준으로 고정합니다.

## 14-1. 1단계 배포 완료 기준 — 외부 브랜드 골격 완성

### 포함 범위

* 메인 홈
* 회사소개
* 사업소개
* 뉴스레터 리스트 골격
* 문의하기 화면 골격
* 공통 헤더/푸터
* 디자인 토큰 1차 적용

### 완료 기준

* 방문자가 첫 화면에서 AI 서비스 회사로 인식
* 5개 메뉴 구조 고정
* 회사소개에 대표 인사말/과도한 CTA 없음
* 사업소개 순서가 올바름
* 뉴스레터가 3탭 구조를 가짐
* 문의 페이지가 실제 폼 형태를 가짐
* PC/모바일/태블릿 기본 레이아웃이 깨지지 않음

## 14-2. 2단계 배포 완료 기준 — 반응형/다국어/도메인 체계 완성

### 포함 범위

* `src/lib/i18n.ts`
* 언어 선택기
* 언어별 라우트
* canonical / hreflang 정책
* `www.jinbizman.com` 기준 URL 정책
* 반응형 보강

### 완료 기준

* 한국어/영어/일본어/불어/스페인어 라우트 구조 동작
* 언어 전환 시 동일 페이지 유지
* 미발행 언어는 fallback이 아니라 숨김 처리
* `www.jinbizman.com` 기준 SEO가 정리
* 360px~1440px 이상에서 가로 스크롤 없음
* 버튼 겹침/카드 이탈/텍스트 깨짐 없음

## 14-3. 3단계 배포 완료 기준 — 뉴스레터 상세와 문의 실제 동작 완성

### 포함 범위

* 뉴스 리스트/상세 연결
* `보도자료 / 공시정보 / 공지사항` 카테고리 분리
* 문의 저장 API 연결
* 완료 메시지 상태
* EmptyState / ErrorState / LoadingState 보강

### 완료 기준

* 뉴스 탭별 상세 이동 가능
* 상세 SEO와 locale-aware 링크가 동작
* 문의 제출 시 저장 성공
* 문의 완료 메시지가 언어별로 보임
* 빈 상태와 에러 상태가 어색하지 않음

## 14-4. 4단계 배포 완료 기준 — 관리자 운영 연동 가능한 공개 구조 완성

### 포함 범위

* `worker/routes/public/site-pages.ts`
* `worker/routes/public/news.ts`
* `worker/routes/public/inquiries.ts`
* `worker/routes/public/locales.ts`
* summary/detail 응답 구조 정리

### 완료 기준

* 공개 페이지가 관리자 콘텐츠 모델과 연결 가능한 구조를 가짐
* 뉴스와 문의가 관리자 ERP 운영 흐름으로 이어짐
* 언어별 게시 상태와 공개 여부가 프론트에 반영됨
* 공개 페이지가 하드코딩만으로 끝나지 않고 운영형 구조를 가짐

## 14-5. 5단계 배포 완료 기준 — 공개 사이트 최종 검수 완료

### 포함 범위

* 전체 페이지 QA
* 다국어/SEO 최종 검수
* 반응형 최종 검수
* 링크/폼/상태/NotFound 검수

### 완료 기준

* 외부 5개 메뉴가 모두 안정적으로 동작
* 뉴스레터 3탭 구조가 어긋나지 않음
* 문의 저장 흐름과 완료 상태가 정상 동작
* 다국어 전환 후 레이아웃 파손 없음

* 기존 `public-site-ia.md`를 이 문서로 바로 교체 가능

# 15. 문서 교체용 최종 체크리스트

## 15-1. 이 문서가 기존 `public-site-ia.md`를 즉시 대체할 수 있어야 하는 이유

* 외부 사이트의 1차 상위 메뉴가 명확히 정리돼 있습니다.
* 각 메뉴의 역할과 섹션 구조가 정리돼 있습니다.
* 메인 홈, 회사소개, 사업소개, 뉴스레터, 문의하기의 페이지 위계가 포함돼 있습니다.
* 대표 사용자 흐름이 포함돼 있습니다.
* 5개 언어 URL 구조, canonical, SEO 규칙이 포함돼 있습니다.
* 반응형 IA 규칙이 포함돼 있습니다.
* 1차 구현 우선순위와 절대 빠지면 안 되는 연결 규칙이 포함돼 있습니다.
* 5단계 배포 완료 기준이 포함돼 있습니다.

## 15-2. 최종 검수 체크리스트

### 메뉴 구조
* 메인 홈
* 회사소개
* 사업소개
* 뉴스레터
* 문의하기

### 핵심 흐름
* 메인 홈 → 회사소개
* 메인 홈 → 사업소개
* 메인 홈 → 뉴스레터
* 메인 홈 → 문의하기
* 뉴스레터 → 상세
* 문의하기 → 완료 상태

### 운영 정책
* 5개 언어
* `www.jinbizman.com`
* 모바일/태블릿/데스크톱 반응형
* AI 서비스 회사 인식
* 뉴스레터 3탭 구조
* 문의 저장 구조 연결
* 5단계 배포 완료 기준 반영

## 변경 요약

* `docs/IA/public-site-ia.md`를 **외부 공개 사이트 정보구조 전용 실행 문서**로 재정의했습니다.
* 5개 상위 메뉴, 페이지 역할, 섹션 구조, 사용자 흐름, 다국어/도메인/SEO 규칙을 정리했습니다.
* 뉴스레터의 실제 구조와 문의 전환 구조를 IA 관점으로 반영했습니다.
* 반응형, 5개 언어, `www.jinbizman.com` 정책을 외부 사이트 운영 관점으로 내려 정리했습니다.
* 1차 구현 우선순위와 절대 빠지면 안 되는 연결 규칙, 그리고 **5단계 배포 완료 기준**까지 포함했습니다.
